قبل از شروع: چهار نکته‌ی صادقانه

  1. مخزن باید عمومی (Public) باشد. سهمیه‌ی رایگان مخزن خصوصی ماهانه ۲۰۰۰ دقیقه است و این ربات ماهانه حدود ۶۰۰۰ تا ۷۳۰۰ دقیقه اجرا می‌شود. عمومی بودن یعنی کد ربات (منطق ستاپ) و ناحیه‌هایی که هر روز ثبت می‌شوند (در شاخه‌ی bot-state) برای هر کسی که مخزن را پیدا کند دیدنی است. توکن ربات و شناسه‌ی چت در Secrets می‌مانند و دیده نمی‌شوند.
  2. شرایط استفاده‌ی GitHub یک نقطه‌ی خاکستری دارد. GitHub می‌نویسد روی اجراکننده‌های خودش هر فعالیتی که به تولید، تست، استقرار یا انتشار پروژه‌ی نرم‌افزاری مربوط نباشد نباید انجام شود (متن شرایط). اجرای زمان‌بندی‌شده‌ی یک ربات رصد بازار به این منطقه نزدیک است: رایج است، ولی نمی‌توانم تضمین کنم GitHub ایرادی نگیرد. برای این ربات یک مخزن جدا بسازید و برای حالت توقف، بخش «اگر GitHub اجرا را متوقف کرد» را ببینید.
  3. تأخیر واقعی هنوز اندازه‌گیری نشده. از محیطی که من کار می‌کردم اتصال به Yahoo و تلگرام ممکن نبود؛ پس تأخیر واقعی داده و پیام را نمی‌توانم تضمین کنم. مرحله‌ی ۸ آن را از خود سرور GitHub اندازه می‌گیرد. قبل از تکیه بر ربات برای معامله‌ی واقعی، آن را در ساعت بازار اجرا کنید.
  4. قیمت شاخص‌ها از فیوچرز است. برای NAS100، US30 و SPX500 داده‌ی رایگانِ فیوچرز (NQ=F، YM=F، ES=F) استفاده می‌شود، چون شاخص نقدی قبل از ۰۹:۳۰ نیویورک کندل ندارد. ساختار کندل‌ها همان است ولی سطح قیمت ممکن است از چند پوینت تا چند صد پوینت با CFD بروکر شما فرق کند. برای نزدیک‌کردنشان بخش «تنظیمات اختیاری» را ببینید.
۱

حساب GitHub

اگر حساب GitHub ندارید از github.com/signup بسازید و وارد شوید. ربات روی سرورهای GitHub اجرا می‌شود؛ بعد از راه‌اندازی هیچ چیزی روی کامپیوتر یا اینترنت شما نمی‌ماند.

نکته
طبق صفحه‌ی GitHub and export controls، GitHub برای توسعه‌دهندگان ایران مجوز گرفته و خدمات رایگان و پولی‌اش در دسترس است. تحریم‌ها ممکن است تغییر کنند و من ثبت‌نام را از اینجا آزمایش نکرده‌ام.
۲

ساخت مخزن عمومی (Public)

  1. بالای صفحه روی + و بعد New repository بزنید.
  2. در Repository name بنویسید: ny1m-bot
  3. گزینه‌ی Public را انتخاب کنید.
  4. تیک Add a README file را بزنید.
  5. روی Create repository بزنید.
نکته
چرا Public؟ در مخزن عمومی دقیقه‌ی اجرای GitHub Actions رایگان است؛ مخزن خصوصی ماهانه فقط ۲۰۰۰ دقیقه‌ی رایگان دارد. توکن و شناسه‌ی چت در کد نیستند و در مرحله‌ی ۶ داخل Secrets می‌روند.
مراقب باشید
عمومی بودن یعنی کد ربات و ناحیه‌های ثبت‌شده‌ی هر روز (شاخه‌ی bot-state) برای هر کسی که مخزن را پیدا کند دیدنی است. اگر این برایتان مهم است، بخش «اگر GitHub اجرا را متوقف کرد» را هم ببینید: همان کد روی کامپیوتر یا سرور خودتان هم اجرا می‌شود.
۳

بارگذاری فایل‌های ربات

  1. فایل ny1m-bot.zip را از حالت فشرده خارج (Extract) کنید. پوشه‌ای به نام ny1m-bot ساخته می‌شود.
  2. در صفحه‌ی مخزن: Add file ← Upload files.
  3. وارد پوشه‌ی ny1m-bot شوید، همه‌ی محتوای داخل آن را انتخاب کنید و داخل صفحه‌ی مرورگر بکشید (خودِ پوشه را نکشید). پوشه‌ی .github هم باید جزو آن‌ها باشد.
  4. صبر کنید همه‌ی فایل‌ها بارگذاری شوند و بعد Commit changes را بزنید.
نکته
در مک، پوشه‌هایی که با نقطه شروع می‌شوند مخفی‌اند. در Finder کلیدهای Cmd + Shift + . را بزنید تا .github دیده شود.

بررسی: در صفحه‌ی اصلی مخزن باید پوشه‌های .github، bot، tests، tools و فایل requirements.txt را ببینید. اگر .github نبود، به بخش «روش دستی برای فایل‌های workflow» در پایین همین صفحه بروید.

۴

ساخت ربات تلگرام

  1. در تلگرام @BotFather را باز کنید (تیک آبی داشته باشد) و /newbot را بفرستید.
  2. یک اسم دلخواه بدهید، بعد یک نام کاربری که به bot ختم شود (مثلاً my_ny1m_bot).
  3. BotFather یک توکن می‌دهد، شبیه 123456789:AAH…. آن را کپی کنید و جای امن نگه دارید.
  4. ربات تازه‌ساخته‌تان را باز کنید و دکمه‌ی Start را بزنید (بدون این کار ربات نمی‌تواند به شما پیام بدهد).
مراقب باشید
توکن مثل رمز عبور است. در گروه، کانال یا هیچ جای عمومی نگذارید.
۵

پیدا کردن شناسه‌ی چت (Chat ID)

ساده‌ترین حالت این است که پیام‌ها در چت خصوصی خودتان با ربات بیایند. یکی از دو راه را بروید:

  1. در تلگرام @userinfobot را باز کنید و Start بزنید. عددی که جلوی Id می‌نویسد شناسه‌ی شماست (مثلاً 123456789).
  2. یا در مرورگر آدرس زیر را باز کنید (به‌جای TOKEN توکن خودتان را بگذارید) و عدد جلوی "chat":{"id": را بردارید:
URL
https://api.telegram.org/botTOKEN/getUpdates
نکته
اگر خروجی "result":[] بود، یک پیام برای ربات بفرستید و صفحه را دوباره باز کنید. برای دریافت پیام‌ها در کانال یا گروه: آن را بسازید، ربات را Admin کنید، یک پیام داخلش بفرستید و با همان آدرس شناسه را بردارید. شناسه‌ی کانال با -100 شروع می‌شود و علامت منفی هم جزو عدد است.
۶

ثبت توکن و شناسه در GitHub (Secrets)

  1. در مخزن: Settings ← Secrets and variables ← Actions.
  2. New repository secret را بزنید. در Name بنویسید TELEGRAM_BOT_TOKEN و در Secret توکن را بچسبانید ← Add secret.
  3. دوباره New repository secret: نام TELEGRAM_CHAT_ID و مقدارش شناسه‌ی چت ← Add secret.

نام‌ها را از اینجا کپی کنید تا غلط نشوند:

نام Secret
TELEGRAM_BOT_TOKEN
نام Secret
TELEGRAM_CHAT_ID
نکته
نام‌ها باید دقیقاً همین‌ها باشند (حروف بزرگ، بدون فاصله). Secret باید در سطح مخزن (Repository secret) باشد.

اختیاری: پشتیبان داده برای فارکس و طلا

Yahoo منبع اصلی هر ۶ نماد است. اگر کلید رایگان Twelve Data داشته باشید، در صورت خطای پیاپی Yahoo برای EURUSD، GBPUSD و XAUUSD ربات خودکار به آن می‌رود. سقف رایگان ۸ درخواست در دقیقه است و برای شاخص‌ها پشتیبان رایگان وجود ندارد.

  1. در twelvedata.com ثبت‌نام کنید و API key را کپی کنید.
  2. یک Secret سوم بسازید و کلید را در آن بچسبانید:
نام Secret
TWELVEDATA_API_KEY
۷

تست اتصال و selftest

  1. بالای مخزن Actions را بزنید. اگر GitHub دکمه‌ی فعال‌سازی نشان داد (I understand my workflows, go ahead and enable them) آن را بزنید.
  2. از ستون چپ تست: اتصال تلگرام و selftest را انتخاب کنید ← Run workflow ← دوباره Run workflow.
  3. بعد از چند دقیقه تیک سبز ظاهر می‌شود.

در تلگرام باید ۵ پیام ببینید: یک پیام تست و دو نمونه‌ی چارت (یکی فروش، یکی خرید) که هرکدام یک ریپلای «ورود به ناحیه» دارند. این‌ها داده‌ی ساختگی‌اند و فقط ظاهر پیام‌ها را نشان می‌دهند.

نکته
اگر ✗ قرمز شد: روی اجرا کلیک کنید، مرحله‌ی قرمز را باز کنید و متن خطا را برای من بفرستید.
۸

سنجش تأخیر منابع داده

این مرحله نشان می‌دهد داده‌ی Yahoo از سرور GitHub چند ثانیه دیر می‌رسد. دوشنبه تا جمعه و داخل بازه‌ی ۰۸:۳۰ تا ۱۱:۳۰ نیویورک اجرا کنید (زمستان ۱۷:۰۰ تا ۲۰:۰۰ تهران، تابستان ۱۶:۰۰ تا ۱۹:۰۰). آخر هفته بازار بسته است و فقط دسترسی بررسی می‌شود.

  1. Actions ← سنجش منابع داده (تأخیر واقعی) ← Run workflow (عدد ۱۲ را نگه دارید؛ حدود ۱۵ دقیقه طول می‌کشد).
  2. بعد از پایان روی همان اجرا کلیک کنید؛ در صفحه‌ی Summary جدول نتیجه است.
  3. ستون «ارزیابی» را ببینید: «عالی» یا «قابل قبول» یعنی خوب است و «کند» یعنی تأخیر بیشتر از هدف است.
نکته
معیار: «عالی» یعنی میانه‌ی تأخیر ≤ ۸ ثانیه و ۹۰٪ موارد ≤ ۱۵ ثانیه؛ «قابل قبول» یعنی ≤ ۲۰ و ≤ ۴۰ ثانیه. این آزمون هر دقیقه فقط چند درخواست می‌فرستد، مثل خود ربات.
مراقب باشید
اگر همه‌ی تیکرها ❌ شدند و خطای HTTP 429 یا 403 دیدید، یعنی Yahoo جلوی سرورهای GitHub را گرفته. نتیجه را برایم بفرستید تا منبع را عوض کنیم.
۹

بک‌تست روی داده‌ی واقعی

  1. Actions ← بک‌تست روی داده‌ی واقعی ۱ دقیقه ← Run workflow (روزها: ۲۰).
  2. بعد از پایان، پایین صفحه‌ی اجرا در بخش Artifacts فایل backtest-result را دانلود کنید.
  3. report.md خلاصه است، zones.csv فهرست همه‌ی ناحیه‌ها و پوشه‌ی charts نمونه‌ی چارت‌ها.

چند مورد را با چارت خودتان مقایسه کنید: خط آبی باید روی سطح سویینگِ هانت‌شده باشد (نه نوک شدو) و خط نارنجی روی سویینگ شکسته‌شده. اگر موردی به نظرتان غلط بود، تاریخ، نماد و ساعتش را برایم بفرستید.

نکته
Yahoo فقط حدود ۳۰ روز اخیر را به‌صورت ۱ دقیقه‌ای می‌دهد؛ بیشترین مقدار مجاز ۲۹ روز است. قیمت شاخص‌ها فیوچرز است.
۱۰

اجرای خودکار روزانه

کار خاصی لازم نیست. فایل bot.yml ربات را دوشنبه تا جمعه خودکار اجرا می‌کند: حدود ساعت ۱۰:۵۰ UTC (۱۴:۲۰ تهران) شروع می‌شود، تا ۰۸:۲۰ نیویورک می‌خوابد، تاریخچه را می‌گیرد و از ۰۸:۳۰ تا ۱۱:۳۰ رصد می‌کند. ساعت تابستانی و زمستانی آمریکا را خودش حساب می‌کند.

برای دیدن اجرای زنده: Actions ← ربات ستاپ ۱ دقیقه‌ای (اجرای روزانه) ← اجرای در حال انجام (زرد) ← کلیک ← لاگ.

نکته
طبق مستندات GitHub، اجرای زمان‌بندی‌شده می‌تواند دیر شروع شود و در بار زیاد ممکن است حذف شود. برای همین سه زمان‌بندی زودتر از بازه تعریف شده و مرحله‌ی بعد یک trigger پشتیبان می‌سازد.
مراقب باشید
اگر ۶۰ روز هیچ فعالیتی در مخزن نباشد، GitHub زمان‌بندی را خاموش می‌کند. ربات هر ۴۰ روز یک commit خالی می‌زند تا این اتفاق نیفتد. اگر ایمیل هشدار گرفتید، در Actions گزینه‌ی Enable workflow را بزنید.
۱۱

trigger پشتیبان با cron-job.org

اگر زمان‌بندی GitHub رد شد یا خیلی دیر اجرا شد، این سرویس رایگان ربات را صدا می‌زند. اگر دو ربات هم‌زمان شروع شوند فقط یکی کار می‌کند؛ دومی منتظر می‌ماند و بعد از پایان بازه بی‌سروصدا خارج می‌شود. این مرحله توصیه می‌شود ولی اجباری نیست.

الف) ساخت توکن GitHub

  1. در GitHub: عکس پروفایل ← Settings ← پایین ستون چپ Developer settings ← Personal access tokens ← Fine-grained tokens ← Generate new token.
  2. Token name: cronjob-ny1m و Expiration: یک سال (یادداشت کنید سال بعد تمدید شود).
  3. Repository access ← Only select repositories ← ny1m-bot.
  4. Permissions ← Repository permissions ← Actions ← Read and write.
  5. Generate token و توکنی را که با github_pat_ شروع می‌شود کپی کنید (فقط یک‌بار نشان داده می‌شود).

ب) ساخت job در cron-job.org

  1. در cron-job.org ثبت‌نام کنید و Create cronjob را بزنید. Title: ny1m start
  2. در URL آدرس زیر را بگذارید و USERNAME را با نام کاربری GitHub خودتان عوض کنید:
URL
https://api.github.com/repos/USERNAME/ny1m-bot/actions/workflows/bot.yml/dispatches
  1. Execution schedule ← User-defined: منطقه‌ی زمانی America/New_York، روزها دوشنبه تا جمعه، ساعت‌ها 7 و 8، دقیقه 0.
  2. تب Advanced: Request method را POST بگذارید و این چهار هدر را اضافه کنید (نام و مقدار جدا):
هدرها
Accept: application/vnd.github+json
Authorization: Bearer github_pat_YOUR_TOKEN
X-GitHub-Api-Version: 2022-11-28
Content-Type: application/json

در Request body این را بگذارید:

JSON
{"ref":"main"}

Save و بعد Test run را بزنید. پاسخ درست 204 است و در Actions یک اجرای تازه با برچسب workflow_dispatch پیدا می‌شود.

نکته
اگر نام مخزن یا شاخه‌ی پیش‌فرض‌تان فرق دارد (مثلاً master)، آن را در آدرس و بدنه عوض کنید. رابط سایت ممکن است کمی فرق کند؛ معادل هر گزینه را انتخاب کنید. اگر ثبت‌نام در cron-job.org ممکن نبود این مرحله را رد کنید: سه زمان‌بندی خود GitHub هم کار می‌کند و فقط احتمال نادرِ رد شدن را پوشش نمی‌دهد.

هر روز چه می‌بینید

  • ۰۸:۳۰ نیویورک (زمستان ۱۷:۰۰ تهران، تابستان ۱۶:۰۰): پیام بی‌صدای «ربات روشن است».
  • هر ناحیه: یک عکس چارت با کپشن. هدف ۱۰ تا ۲۰ ثانیه بعد از کلوز کندل است؛ عدد واقعی را مرحله‌ی ۸ و پیام پایان بازه نشان می‌دهند.
  • اولین رسیدن قیمت به لبه‌ی ورود (حتی داخل کندل در حال شکل‌گیری): ریپلای کوتاه روی همان پیام ناحیه، فقط یک‌بار.
  • ۱۱:۳۰: پیام بی‌صدای پایان با تعداد ناحیه‌ها و آمار تأخیر همان روز.
  • اگر داده قطع شود: پیام «هشدار: قطع داده»؛ وقتی برگشت، یک پیام بی‌صدا.

تعداد کندل چارت (۶۰ تا ۹۰)

پیام پایان بازه بی‌صدا باشد؟

برای خاموش کردن ربات: Actions ← ربات ستاپ ۱ دقیقه‌ای (اجرای روزانه) ← منوی … ← Disable workflow.

رفع مشکل

پیامی نیامد
Actions را باز کنید و اجرای امروز را ببینید. اگر خطای «TELEGRAM_BOT_TOKEN و TELEGRAM_CHAT_ID تنظیم نشده‌اند» بود، نام Secretها را با مرحله‌ی ۶ مقایسه کنید.
خطای Unauthorized یا chat not found
Unauthorized یعنی توکن غلط یا ناقص کپی شده. chat not found یعنی Start را در ربات نزده‌اید، شناسه غلط است، یا ربات در کانال Admin نیست.
اجرای روزانه شروع نشد یا دیر شروع شد
در Actions ببینید workflow فعال است یا نه. GitHub ممکن است زمان‌بندی را دیر اجرا کند؛ trigger پشتیبان (مرحله‌ی ۱۱) برای همین است. می‌توانید با Run workflow دستی هم اجرا کنید: اگر بازه شروع شده باشد، ربات وسط بازه وارد می‌شود و ناحیه‌های قبلی را با برچسب «ارسال با تأخیر» می‌فرستد.
قیمت‌ها با چارت بروکرم فرق دارد
برای NAS100، US30 و SPX500 داده‌ی فیوچرز (NQ=F، YM=F، ES=F) است و با CFD بروکر اختلاف دارد؛ ساختار کندل‌ها یکی است. اگر خواستید PRICE_OFFSET را تنظیم کنید.
هشدار قطع داده در تعطیلات آمریکا
در روزهای تعطیل بازار آمریکا (مثل تشکر و کریسمس) کندل‌ها کم یا قطع می‌شوند و هشدار طبیعی است.
خطای 429 از Yahoo
یعنی Yahoo درخواست‌ها را محدود کرده. ربات خودکار صبر می‌کند و دوباره تلاش می‌کند و برای فارکس و طلا (اگر کلید Twelve Data دارید) به پشتیبان می‌رود. اگر مدام تکرار شد، نتیجه‌ی مرحله‌ی ۸ را برایم بفرستید.
در لاگ نوشته state push failed یا Permission denied
ربات بدون ذخیره‌ی وضعیت هم کار می‌کند، ولی بعد از ری‌استارت ممکن است ناحیه‌ی قبلی دوباره ارسال شود. در مخزن: Settings ← Actions ← General ← پایین صفحه Workflow permissions ← Read and write permissions ← Save.
GitHub هشدار داد یا اجرا را غیرفعال کرد
پیام GitHub را بخوانید. اگر به شرایط استفاده از Actions مربوط بود، از بخش «اگر GitHub اجرا را متوقف کرد» استفاده کنید.

اگر GitHub اجرا را متوقف کرد

همین کد روی هر کامپیوتر یا سرور دیگری هم اجرا می‌شود؛ فقط باید Python 3.12 داشته باشد و حداقل از ساعت ۰۸:۲۰ نیویورک روشن و آنلاین باشد. ربات خودش منتظر شروع بازه می‌ماند و بعد از ۱۱:۳۰ خارج می‌شود. هر روز یک‌بار اجرایش کنید، یا آن را با Task Scheduler (ویندوز) یا cron (مک و لینوکس) زمان‌بندی کنید.

تصمیم

  • انتخاب فعلی: منبع اصلی Yahoo برای هر ۶ نماد و پشتیبان Twelve Data فقط برای فارکس و طلا. برای شاخص‌ها پشتیبان رایگانِ قابل‌اعتماد پیدا نکردم.

ریسک‌هایی که باید بدانید

  • شرایط استفاده‌ی GitHub: اجرای رایگان روی اجراکننده‌های GitHub باید به پروژه‌ی نرم‌افزاری مخزن مربوط باشد؛ ربات رصد بازار در منطقه‌ی خاکستری است (متن شرایط). برنامه‌ی جایگزین در راهنما هست.
  • مخزن عمومی: کد و ناحیه‌های ثبت‌شده‌ی هر روز برای هر کسی که مخزن را پیدا کند دیدنی است؛ توکن و شناسه‌ی چت نه.
  • Yahoo ممکن است محدود یا مسدود کند (۴۲۹ یا ۴۰۳). ربات صبر می‌کند و پیام «قطع داده» می‌فرستد؛ برای فارکس و طلا در صورت داشتن کلید به Twelve Data می‌رود، برای شاخص‌ها پشتیبانی ندارد.
  • کیفیت XAUUSD=X در Yahoo تأیید نشد. اگر کم یا کهنه بود ربات خودکار GC=F (فیوچرز طلا) را انتخاب می‌کند و قیمت چند دلار بالاتر از اسپات خواهد بود.
  • شاخص‌ها فیوچرز هستند، چون شاخص نقدی قبل از ۰۹:۳۰ نیویورک کندل ندارد. ساختار یکی است ولی سطح قیمت با CFD بروکر فرق می‌کند.
  • زمان‌بندی GitHub: طبق مستندات می‌تواند دیر شود و در بار زیاد حذف شود. با شروع زودهنگام، سه زمان‌بندی و trigger پشتیبان پوشش داده شده، ولی صددرصد تضمین نیست.
  • تعطیلات آمریکا: کندل‌ها کم یا قطع می‌شوند و هشدار «قطع داده» طبیعی است.

روش دستی برای فایل‌های workflow

اگر بعد از بارگذاری، پوشه‌ی .github در مخزن نبود، هر چهار فایل را این‌طور بسازید:

  1. در مخزن: Add file ← Create new file.
  2. در کادر نام فایل، مسیر را تایپ کنید، مثلاً .github/workflows/bot.yml (با تایپ / پوشه‌ها خودکار ساخته می‌شوند).
  3. محتوای همان فایل را از پایین کپی و در کادر بزرگ بچسبانید، بعد Commit changes.
  4. همین کار را برای test.yml، probe.yml و backtest.yml تکرار کنید.
نکته
همین چهار فایل داخل zip هم در پوشه‌ی workflow-files هست و می‌توانید از آنجا باز کنید و کپی کنید.
.github/workflows/bot.yml
name: "ربات ستاپ ۱ دقیقه‌ای (اجرای روزانه)"

# ساعت‌ها UTC هستند. ربات خودش زمان نیویورک (با ساعت تابستانی/زمستانی) را حساب می‌کند.
# ۱۰:۵۰ UTC یعنی ۰۵:۵۰ نیویورک در زمستان و ۰۶:۵۰ در تابستان؛ مدتی زودتر از ۰۸:۳۰ تا تأخیر احتمالی GitHub جبران شود.
# سه زمان‌بندی یکی‌اند و فقط یک ربات هم‌زمان اجرا می‌شود (concurrency)؛ بقیه پشتیبان‌اند.
on:
  schedule:
    - cron: "50 10 * * 1-5"
    - cron: "50 11 * * 1-5"
    - cron: "10 12 * * 1-5"
  workflow_dispatch:

concurrency:
  group: ny-setup-bot
  cancel-in-progress: false

permissions:
  contents: write

jobs:
  bot:
    runs-on: ubuntu-latest
    timeout-minutes: 350
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip

      - name: نصب کتابخانه‌ها
        run: pip install -r requirements.txt

      - name: آماده‌سازی شاخه‌ی ذخیره‌ی وضعیت
        run: bash tools/prepare_state.sh

      - name: اجرای ربات
        env:
          TELEGRAM_BOT_TOKEN: ${{ secrets.TELEGRAM_BOT_TOKEN }}
          TELEGRAM_CHAT_ID: ${{ secrets.TELEGRAM_CHAT_ID }}
          TWELVEDATA_API_KEY: ${{ secrets.TWELVEDATA_API_KEY }}
        run: python -u -m bot.runner

      - name: جلوگیری از غیرفعال‌شدن زمان‌بندی (هر ~۴۰ روز یک commit خالی)
        if: always()
        run: |
          branch="${{ github.event.repository.default_branch }}"
          last=$(git log -1 --format=%ct HEAD)
          now=$(date +%s)
          if [ $(( (now - last) / 86400 )) -ge 40 ]; then
            git commit --allow-empty -qm "keepalive" && git push origin "HEAD:${branch}" || true
          fi
